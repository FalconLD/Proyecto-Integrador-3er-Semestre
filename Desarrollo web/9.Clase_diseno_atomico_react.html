Clase: Diseño Atómico en React

Organiza tus componentes React de forma escalable y mantenible — arquitectura de componentes.

Objetivo

Aprender la metodología de Diseño Atómico para organizar componentes React de forma escalable y mantenible. Entender cómo estructurar componentes desde los más simples (átomos) hasta los más complejos (páginas), y cómo integrar frameworks de UI como Material UI o Ant Design en esta arquitectura.

⚛️ ¿Qué es el Diseño Atómico?

El Diseño Atómico es una metodología creada por Brad Frost que organiza los componentes de una interfaz de usuario en una jerarquía clara y lógica, similar a cómo se organizan los átomos en química.

Concepto fundamental

Así como en química los átomos se combinan para formar moléculas, y las moléculas forman organismos, en el diseño atómico los componentes pequeños se combinan para formar componentes más grandes y complejos.

Los 5 niveles del diseño atómico

  1. Átomos: Los componentes más pequeños e indivisibles (botones, inputs, etiquetas)
  2. Moléculas: Combinaciones simples de átomos (formularios de búsqueda, tarjetas de producto)
  3. Organismos: Componentes complejos formados por moléculas y átomos (headers, sidebars, listas de productos)
  4. Templates: Estructuras de página sin contenido real (wireframes con componentes)
  5. Páginas: Templates con contenido real (la versión final que ve el usuario)

¿Por qué usar diseño atómico?

  • Organización clara: Sabes exactamente dónde encontrar cada componente
  • Reutilización: Los componentes pequeños se reutilizan fácilmente
  • Mantenibilidad: Cambios en un átomo se propagan automáticamente
  • Colaboración: Diferentes personas pueden trabajar en diferentes niveles
  • Testing: Es más fácil testear componentes pequeños y aislados
  • Consistencia: Usar los mismos átomos garantiza consistencia visual
  • Escalabilidad: Fácil agregar nuevos componentes sin desorganizar el proyecto

💡 Analogía: Piensa en construir con bloques de LEGO. Los átomos son las piezas individuales, las moléculas son construcciones pequeñas, los organismos son construcciones grandes, y las páginas son el modelo completo.

🔬 Los 5 Niveles en Detalle

Vamos a explorar cada nivel con ejemplos prácticos en React.

1. Átomos (Atoms)

Los componentes más pequeños e indivisibles. No pueden descomponerse más sin perder su funcionalidad.

  • Características: Muy simples, sin lógica compleja, altamente reutilizables
  • Ejemplos: Botones, inputs, etiquetas, iconos, imágenes, títulos
  • Props: Reciben props básicas (texto, onClick, disabled, etc.)

Ejemplo: Botón como Átomo

// components/atoms/Button/Button.jsx
const Button = ({ children, onClick, variant = 'primary', disabled = false }) => {
  return (
    <button 
      onClick={onClick} 
      disabled={disabled}
      className={`btn btn-${variant}`}
    >
      {children}
    </button>
  );
};

export default Button;

2. Moléculas (Molecules)

Combinaciones simples de átomos que funcionan juntos como una unidad.

  • Características: Combinan 2-5 átomos, tienen una función específica
  • Ejemplos: Formularios de búsqueda, tarjetas de producto, campos de formulario con label
  • Props: Reciben props más complejas relacionadas con su función

Ejemplo: Campo de Búsqueda como Molécula

// components/molecules/SearchBox/SearchBox.jsx
import Button from '../../atoms/Button/Button';
import Input from '../../atoms/Input/Input';

const SearchBox = ({ onSearch, placeholder = "Buscar..." }) => {
  const [searchTerm, setSearchTerm] = useState('');

  const handleSubmit = (e) => {
    e.preventDefault();
    onSearch(searchTerm);
  };

  return (
    <form onSubmit={handleSubmit} className="search-box">
      <Input
        value={searchTerm}
        onChange={(e) => setSearchTerm(e.target.value)}
        placeholder={placeholder}
      />
      <Button type="submit">Buscar</Button>
    </form>
  );
};

export default SearchBox;

3. Organismos (Organisms)

Componentes complejos formados por moléculas, átomos y a veces otros organismos.

  • Características: Componentes grandes con lógica compleja, secciones completas de UI
  • Ejemplos: Headers con navegación, listas de productos, formularios completos, sidebars
  • Props: Reciben datos y funciones más complejas

Ejemplo: Header como Organismo

// components/organisms/Header/Header.jsx
import Logo from '../../atoms/Logo/Logo';
import Navigation from '../../molecules/Navigation/Navigation';
import SearchBox from '../../molecules/SearchBox/SearchBox';
import Button from '../../atoms/Button/Button';

const Header = ({ user, onLogout }) => {
  return (
    <header className="header">
      <Logo />
      <Navigation items={navItems} />
      <SearchBox onSearch={handleSearch} />
      {user ? (
        <Button onClick={onLogout}>Cerrar Sesión</Button>
      ) : (
        <Button variant="secondary">Iniciar Sesión</Button>
      )}
    </header>
  );
};

export default Header;

4. Templates

Estructuras de página que muestran la disposición de los componentes sin contenido real.

  • Características: Muestran la estructura, usan contenido placeholder
  • Ejemplos: Layout de página de productos, layout de dashboard
  • Props: Pueden recibir datos de ejemplo o estar vacíos

Ejemplo: Template de Página de Productos

// components/templates/ProductPageTemplate/ProductPageTemplate.jsx
import Header from '../../organisms/Header/Header';
import Sidebar from '../../organisms/Sidebar/Sidebar';
import ProductList from '../../organisms/ProductList/ProductList';

const ProductPageTemplate = () => {
  return (
    <div className="product-page-template">
      <Header />
      <div className="content">
        <Sidebar />
        <main>
          <ProductList products={[]} />
        </main>
      </div>
    </div>
  );
};

export default ProductPageTemplate;

5. Páginas (Pages)

Templates con contenido real. Son las versiones finales que los usuarios ven.

  • Características: Contienen datos reales, conectan con APIs, manejan estado
  • Ejemplos: Página de inicio, página de productos, página de perfil
  • Props: Pueden recibir datos de rutas, APIs, o estado global

Ejemplo: Página de Productos

// pages/ProductsPage.jsx
import { useState, useEffect } from 'react';
import ProductPageTemplate from '../components/templates/ProductPageTemplate/ProductPageTemplate';
import ProductList from '../components/organisms/ProductList/ProductList';

const ProductsPage = () => {
  const [products, setProducts] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    // Cargar productos desde API
    fetch('/api/products')
      .then(res => res.json())
      .then(data => {
        setProducts(data);
        setLoading(false);
      });
  }, []);

  if (loading) return <div>Cargando...</div>;

  return (
    <ProductPageTemplate>
      <ProductList products={products} />
    </ProductPageTemplate>
  );
};

export default ProductsPage;

📁 Estructura de Carpetas

Organiza tu proyecto React siguiendo la metodología de diseño atómico.

Estructura recomendada

src/
├── components/
│   ├── atoms/
│   │   ├── Button/
│   │   │   ├── Button.jsx
│   │   │   ├── Button.css
│   │   │   └── index.js
│   │   ├── Input/
│   │   │   ├── Input.jsx
│   │   │   ├── Input.css
│   │   │   └── index.js
│   │   ├── Label/
│   │   └── Icon/
│   ├── molecules/
│   │   ├── SearchBox/
│   │   ├── FormField/
│   │   └── ProductCard/
│   ├── organisms/
│   │   ├── Header/
│   │   ├── ProductList/
│   │   └── Sidebar/
│   └── templates/
│       ├── ProductPageTemplate/
│       └── DashboardTemplate/
├── pages/
│   ├── HomePage.jsx
│   ├── ProductsPage.jsx
│   └── ProfilePage.jsx
├── hooks/
├── utils/
├── services/
└── App.jsx

¿Por qué esta estructura?

  • Separación clara: Cada nivel tiene su carpeta
  • Fácil de navegar: Sabes exactamente dónde buscar componentes
  • Escalable: Puedes agregar componentes sin desorganizar
  • Importaciones claras: Las rutas de importación son descriptivas

Archivo index.js para facilitar imports

Cada componente puede tener un index.js para simplificar las importaciones:

// components/atoms/Button/index.js
export { default } from './Button';

// Ahora puedes importar así:
import Button from '../../atoms/Button';
// En lugar de:
// import Button from '../../atoms/Button/Button';

🎨 Integración con Frameworks de UI

Aprende cómo integrar Material UI o Ant Design con el diseño atómico.

¿Qué son Material UI y Ant Design?

  • Material UI (MUI): Framework de componentes React basado en Material Design de Google
  • Ant Design: Framework de componentes React con diseño empresarial
  • Ambos: Proporcionan componentes pre-construidos, estilos, y funcionalidades listas para usar

¿Cómo encajan en el diseño atómico?

Los componentes de estos frameworks pueden servir como átomos base que envuelves o personalizas:

  • Átomos base: Usa los componentes básicos de MUI/Ant Design (Button, Input, etc.)
  • Átomos personalizados: Envuelve o extiende los componentes del framework
  • Moléculas y superiores: Combina estos átomos como siempre

Instalación de Material UI

# Instalar Material UI
npm install @mui/material @emotion/react @emotion/styled

# Instalar iconos (opcional)
npm install @mui/icons-material

Instalación de Ant Design

# Instalar Ant Design
npm install antd

# Si usas Vite, también necesitas:
npm install @vitejs/plugin-react

Ejemplo: Molécula usando átomos de Material UI

// components/molecules/SearchBox/SearchBox.jsx
import { useState } from 'react';
import Button from '../../atoms/Button/Button';
import Input from '../../atoms/Input/Input';
import { TextField } from '@mui/material';
import SearchIcon from '@mui/icons-material/Search';

const SearchBox = ({ onSearch }) => {
  const [searchTerm, setSearchTerm] = useState('');

    e.preventDefault();
    onSearch(searchTerm);
  };

  return (
    <form onSubmit={handleSubmit} style={{ display: 'flex', gap: '8px' }}>
      <TextField
        value={searchTerm}

        placeholder="Buscar..."
        variant="outlined"
        size="small"
      />
      <Button type="submit" variant="contained" startIcon={<SearchIcon />}>
        Buscar
      </Button>
    </form>
  );
};

export default SearchBox;

🎯 Ejemplo Práctico Completo: Gestión de Tareas

Vamos a construir una aplicación de gestión de tareas (To-Do) usando diseño atómico con Material UI.

Átomo: Botón de Estado

// components/atoms/StatusButton/StatusButton.jsx
import { Button } from '@mui/material';

const StatusButton = ({ status, onClick }) => {
  return (
    <Button
      variant={status === 'completed' ? 'contained' : 'outlined'}
      onClick={onClick}
      color={status === 'completed' ? 'success' : 'primary'}
      sx={{
        borderRadius: '8px',
        textTransform: 'none',
      }}
    >
      {status === 'completed' ? 'Completada' : 'Pendiente'}
    </Button>
  );
};

export default StatusButton;

Molécula: Tarjeta de Tarea

// components/molecules/TaskCard/TaskCard.jsx
import { Card, CardContent, Typography, IconButton } from '@mui/material';
import { Delete, Edit } from '@mui/icons-material';
import StatusButton from '../../atoms/StatusButton/StatusButton';

const TaskCard = ({ task, onToggleStatus, onDelete, onEdit }) => {
  return (
    <Card sx={{ minWidth: 300, mb: 2 }}>
      <CardContent>
        <Typography variant="h6" component="div">
          {task.titulo}
        </Typography>
        <Typography color="text.secondary" variant="body2">
          {task.descripcion}
        </Typography>
        <Typography variant="caption" color="text.secondary">
          Fecha: {new Date(task.fecha).toLocaleDateString()}
        </Typography>
        <div style={{ display: 'flex', gap: '8px', marginTop: '16px', alignItems: 'center' }}>
          <StatusButton
            status={task.completada ? 'completed' : 'pending'}
            onClick={() => onToggleStatus(task.id)}
          />
          <IconButton size="small" onClick={() => onEdit(task)}>
            <Edit />
          </IconButton>
          <IconButton size="small" color="error" onClick={() => onDelete(task.id)}>
            <Delete />
          </IconButton>
        </div>
      </CardContent>
    </Card>
  );
};

export default TaskCard;

Organismo: Lista de Tareas

// components/organisms/TaskList/TaskList.jsx
import { Box, Typography } from '@mui/material';
import TaskCard from '../../molecules/TaskCard/TaskCard';

const TaskList = ({ tasks, onToggleStatus, onDelete, onEdit }) => {

  }

  return (
    <Box>
      {tasks.map((task) => (
        <TaskCard
          key={task.id}
          task={task}
          onToggleStatus={onToggleStatus}
          onDelete={onDelete}
          onEdit={onEdit}
        />
      ))}
    </Box>
  );
};

export default TaskList;

Página: Página de Tareas con datos reales

// pages/TasksPage.jsx
import { useState, useEffect } from 'react';
import TasksPageTemplate from '../components/templates/TasksPageTemplate/TasksPageTemplate';

const TasksPage = () => {
  const [tasks, setTasks] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetch('/api/tareas')
      .then(res => res.json())
      .then(data => {
        setTasks(data);
        setLoading(false);
      });
  }, []);

  const handleToggleStatus = (taskId) => {
    // Lógica para cambiar el estado de la tarea
    setTasks(tasks.map(task =>
      task.id === taskId
        ? { ...task, completada: !task.completada }
        : task
    ));
  };

  const handleDelete = (taskId) => {
    // Lógica para eliminar la tarea
    setTasks(tasks.filter(task => task.id !== taskId));
  };

  const handleEdit = (task) => {
    // Lógica para editar la tarea
    console.log('Editar tarea:', task);
  };

  if (loading) return <div>Cargando tareas...</div>;

  return (
    <TasksPageTemplate
      tasks={tasks}
      onToggleStatus={handleToggleStatus}
      onDelete={handleDelete}
      onEdit={handleEdit}
    />
  );
};

export default TasksPage;

✅ Reglas y Buenas Prácticas

Sigue estas reglas para mantener tu código organizado y escalable.

Reglas de los niveles

Nivel Puede usar No puede usar
Átomos Solo estilos propios, props básicas Otros componentes, lógica compleja, estado
Moléculas Átomos, estado local simple Organismos, llamadas a API
Organismos Moléculas, átomos, otros organismos, estado Páginas directamente
Templates Organismos, moléculas, átomos Datos reales, lógica de negocio
Páginas Templates, llamadas a API, estado global Nada (es el nivel más alto)

Buenas prácticas

  • Un componente = un archivo: Cada componente en su propio archivo
  • Nombres descriptivos: Usa nombres claros que indiquen qué hace el componente
  • Props bien definidas: Usa PropTypes o TypeScript para documentar props
  • No saltar niveles: Un organismo no debe usar directamente un átomo si hay una molécula apropiada
  • Reutilización: Si usas el mismo código en 3 lugares, créalo como componente
  • Responsabilidad única: Cada componente debe hacer una cosa bien
  • Composición sobre herencia: Combina componentes pequeños en lugar de crear componentes gigantes

Cuándo crear un nuevo componente

  • ✓ Cuando se repite el mismo código 3+ veces
  • ✓ Cuando un componente tiene más de 100 líneas
  • ✓ Cuando un componente tiene múltiples responsabilidades
  • ✓ Cuando quieres reutilizar una pieza de UI

Cuándo NO crear un nuevo componente

  • ✗ Si solo se usa una vez y es muy específico
  • ✗ Si es solo una línea de JSX simple
  • ✗ Si no tiene lógica ni estilos propios

⚠️ Regla de oro: Si dudas entre dos niveles, elige el nivel más bajo. Es más fácil combinar componentes pequeños que dividir componentes grandes.

⚠️ Errores Comunes

Aprende de los errores más frecuentes al aplicar diseño atómico.

1. Saltar niveles

// ❌ MAL: Organismo usando directamente un átomo
const Header = () => {
  return (
    <header>
      <Button>Login</Button> {/* Debería usar una molécula */}
    </header>
  );
};

// ✅ BIEN: Organismo usando moléculas
const Header = () => {
  return (
    <header>
      <LoginButton /> {/* Molécula que combina Button + lógica */}
    </header>
  );
};

2. Componentes demasiado grandes

// ❌ MAL: Un componente que hace todo
const ProductPage = () => {
  // 200 líneas de código mezclando lógica, UI, y datos
};

// ✅ BIEN: Separado en niveles
const ProductPage = () => {
  return <ProductPageTemplate />;
};

3. Lógica de negocio en átomos

// ❌ MAL: Átomo con lógica compleja
const Button = ({ onClick }) => {
  const handleClick = async () => {
    const data = await fetch('/api/data');
    // ... lógica compleja
    onClick();
  };
  return <button onClick={handleClick}>Click</button>;
};

// ✅ BIEN: Átomo simple, lógica en molécula/organismo
const Button = ({ onClick }) => {
  return <button onClick={onClick}>Click</button>;
};

4. No reutilizar componentes

// ❌ MAL: Duplicar código
const ProductCard1 = () => {
  return <div className="card">...</div>;
};
const ProductCard2 = () => {
  return <div className="card">...</div>; // Mismo código
};

// ✅ BIEN: Reutilizar
const ProductCard = ({ product }) => {
  return <div className="card">...</div>;
};

5. Estructura de carpetas inconsistente

// ❌ MAL: Todo mezclado
components/
  Button.jsx
  SearchBox.jsx
  Header.jsx

// ✅ BIEN: Organizado por niveles
components/
  atoms/Button/
  molecules/SearchBox/
  organisms/Header/

⚖️ Ventajas y Desventajas

Conoce los pros y contras del diseño atómico para decidir cuándo usarlo.

Ventajas

  • ✅ Organización clara: Fácil encontrar componentes
  • ✅ Reutilización: Componentes pequeños se reutilizan fácilmente
  • ✅ Mantenibilidad: Cambios localizados y predecibles
  • ✅ Testing: Más fácil testear componentes pequeños
  • ✅ Colaboración: Múltiples personas pueden trabajar sin conflictos
  • ✅ Consistencia: Usar los mismos átomos garantiza UI consistente
  • ✅ Documentación: La estructura documenta la arquitectura

Desventajas

  • ❌ Overhead inicial: Requiere más planificación al inicio
  • ❌ Muchos archivos: Puede generar muchos archivos pequeños
  • ❌ Curva de aprendizaje: El equipo debe entender la metodología
  • ❌ Puede ser excesivo: Para proyectos muy pequeños puede ser demasiado
  • ❌ Decisiones de nivel: A veces es difícil decidir en qué nivel va un componente

¿Cuándo usar diseño atómico?

  • ✅ Proyectos medianos a grandes (más de 10 componentes)
  • ✅ Equipos de desarrollo (múltiples personas trabajando)
  • ✅ Proyectos de larga duración (que necesitan mantenimiento)
  • ✅ Cuando necesitas reutilización (muchos componentes similares)
  • ✅ Con frameworks de UI (Material UI, Ant Design, etc.)

¿Cuándo NO usar diseño atómico?

  • ❌ Proyectos muy pequeños (prototipos, demos rápidos)
  • ❌ Proyectos de una sola persona (a menos que quieras practicar)
  • ❌ Proyectos con deadline muy ajustado (requiere más tiempo inicial)

Requisitos:

  2. Crea la estructura de carpetas: 
    src/
├── components/
│   ├── atoms/
│   ├── molecules/
│   ├── organisms/
│   └── templates/
└── pages/
  3. Crea los siguientes componentes:
    • Átomos:
      • Button (usando el framework elegido)
      • Input (usando el framework elegido)
      • Card (usando el framework elegido)
      • Typography (usando el framework elegido)
    • Moléculas:
      • BookCard (combina Card + Typography + Button)
      • SearchBox (combina Input + Button)
      • FormField (combina Label + Input)
    • Organismos:
      • Header (con logo, navegación, y SearchBox)
      • BookList (lista de BookCards)
      • BookForm (formulario para agregar/editar libros)
    • Templates:
      • HomePageTemplate (Header + BookList + BookForm)
    • Páginas:
      • HomePage (conecta con API y usa HomePageTemplate)
  4. Conecta con tu API: La página debe cargar libros desde tu API de Express
  5. Funcionalidad:
    • Mostrar lista de libros

    • Agregar nuevos libros

📚 Resumen

Recapitulación de los conceptos más importantes.

Los 5 niveles

  1. Átomos: Componentes más pequeños (Button, Input)
  2. Moléculas: Combinaciones simples (SearchBox, FormField)
  3. Organismos: Componentes complejos (Header, ProductList)
  4. Templates: Estructuras de página sin datos
  5. Páginas: Templates con datos reales

Estructura de carpetas

components/
├── atoms/
├── molecules/
├── organisms/
└── templates/
pages/

Con frameworks de UI

  • Usa los componentes del framework como base para tus átomos
  • Envuelve o personaliza los componentes del framework
  • Combina estos átomos en moléculas y organismos como siempre

Reglas clave

  • ✓ No saltar niveles
  • ✓ Un componente = una responsabilidad
  • ✓ Reutilizar antes de duplicar
  • ✓ Mantener componentes pequeños
  • ✓ Organizar por niveles

💡 Recuerda: El diseño atómico es una guía, no una regla estricta. Adapta la metodología a las necesidades de tu proyecto, pero mantén la organización y la reutilización como principios fundamentales.
