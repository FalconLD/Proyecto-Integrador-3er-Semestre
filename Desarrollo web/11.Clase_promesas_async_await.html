Clase: Promesas y async/await

Manejo de código asíncrono en JavaScript — desarrollo web.

Objetivo

Trabajar con código asíncrono: Promesas, fetch, axios y async/await. Al final podrás hacer peticiones HTTP, leer respuestas JSON y manejar errores para conectar tu frontend con una API.

Ruta de la clase: Asíncrono → Por qué Promesas → Promesas → fetch → axios → async/await → Errores → Resumen. Los primeros ejemplos usan JSONPlaceholder; puedes copiarlos en la consola (F12) y probarlos sin levantar servidor.

⏱️ 1. ¿Qué es código asíncrono?

Operaciones que tardan tiempo (red, disco, etc.) y en las que no queremos que la app se "congele" esperando. El programa sigue haciendo otras cosas y, cuando la operación termina, reaccionamos.

Analogía: pedir comida a domicilio

  • Síncrono (malo): Te quedas parado en la puerta sin hacer nada hasta que llega el pedido.
  • Asíncrono (bueno): Pides, cierras la puerta, sigues viendo series; cuando tocan, abres y recoges.

En una frase: Asíncrono = “avisa cuando termine” en lugar de “espérame aquí bloqueado”.

En código: qué se ejecuta y en qué orden

console.log('A');

setTimeout(() => console.log('B'), 1000);  // "avisa en 1 segundo"

console.log('C');

// Salida: A → C → (1 seg) → B
// "B" no bloquea: el programa sigue y luego responde cuando llega el tiempo

Operaciones típicamente asíncronas

  • Peticiones HTTP (fetch, axios)
  • Leer/escribir archivos
  • Consultas a bases de datos
  • Timers: setTimeout, setInterval

🔗 2. ¿Por qué Promesas? (el problema de los callbacks)

Antes se usaban callbacks. Cuando encadenas varias operaciones asíncronas, el código se vuelve ilegible (“callback hell”) y los errores son difíciles de manejar.

Callback hell (así NO queremos escribir)

// Ejemplo: obtener usuario → después sus posts → después comentarios
getUsuario(1, (usuario) => {
  getPosts(usuario.id, (posts) => {
    getComentarios(posts[0].id, (comentarios) => {
      console.log(comentarios);  // 3 niveles de anidación, difícil de leer
    }, (err) => { /* error comentarios */ });
  }, (err) => { /* error posts */ });
}, (err) => { /* error usuario */ });

En una frase: Las Promesas reemplazan callbacks anidados por una cadena lineal: .then().then().catch()

📦 3. Promesas (Promises)

Un objeto que representa “algo que va a pasar en el futuro”: puede terminar bien (resolve) o mal (reject). Con .then() y .catch() reaccionas cuando eso pase.

Estados (solo 3)

  • pending: aún en curso
  • fulfilled: terminó bien → se usa el valor en .then()
  • rejected: terminó mal → se maneja en .catch()

Crear una Promesa (simular algo que tarda)

const promesa = new Promise((resolve, reject) => {
  setTimeout(() => {
    const todoBien = true;
    if (todoBien) resolve({ mensaje: 'Listo' });
    else         reject(new Error('Falló'));
  }, 1500);
});

Consumir: .then() = éxito, .catch() = error

promesa
  .then((dato) => console.log('Éxito:', dato))
  .catch((err) => console.error('Error:', err));

Encadenar: el “siguiente paso” va en el siguiente .then()

promesa
  .then((dato) => {
    console.log('Paso 1:', dato);
    return 42;  // Este valor llega al siguiente .then()
  })
  .then((num) => console.log('Paso 2:', num))
  .catch((err) => console.error('Cualquier error de la cadena:', err));

🌐 4. fetch() — Peticiones HTTP

fetch(url) hace una petición HTTP y devuelve una Promesa que se resuelve con el objeto response. Para obtener el JSON del cuerpo hay que llamar a response.json(), que también devuelve una Promesa (porque leer el cuerpo es asíncrono).

Dos Promesas seguidas (esto confunde mucho al inicio)

fetch('https://jsonplaceholder.typicode.com/posts/1')
  .then((response) => response.json())   // 1ª Promesa: respuesta de red
  .then((data) => console.log(data));    // 2ª Promesa: body parseado a JSON
// response.json() es una Promesa → por eso hace falta otro .then()

Ejemplo que puedes probar ya (API pública, sin servidor)

Copia esto en la consola del navegador (F12):

fetch('https://jsonplaceholder.typicode.com/users/1')
  .then((res) => res.json())
  .then((user) => console.log('Usuario:', user.name, user.email))
  .catch((err) => console.error('Error de red:', err));

Importante: fetch no falla por 404 o 500

fetch solo rechaza la Promesa si hay error de red (sin internet, URL mala, etc.). Si el servidor responde 404 o 500, la Promesa se cumple; el “error” está en response.ok === false. Hay que comprobarlo a mano: 

fetch('https://jsonplaceholder.typicode.com/posts/99999')
  .then((res) => {
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  })
  .then((data) => console.log(data))
  .catch((err) => console.error(err));

POST: enviar datos en el body

fetch('https://jsonplaceholder.typicode.com/posts', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ title: 'Mi título', body: 'Mi cuerpo', userId: 1 })
})
  .then((res) => res.json())
  .then((nuevo) => console.log('Creado con id:', nuevo.id))
  .catch((err) => console.error(err));

Con tu API (heladería): Cambia la URL por http://localhost:3000/api/sabores (o la ruta que uses). La forma de usar fetch es la misma.

📡 5. axios — Otra forma de hacer peticiones HTTP

axios es una librería que también devuelve Promesas. Muy usada en React y Node. A diferencia de fetch: el body viene como objeto ya parseado en response.data, y rechaza la Promesa en 4xx/5xx (no hay que revisar response.ok a mano).

Cómo usar axios

  • En el navegador (consola): incluye antes un script: <script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script> o abre una página que ya lo cargue.
  • En Node / React: npm install axios y luego import axios from 'axios' o const axios = require('axios').

fetch vs axios (mismo GET)

// fetch: 2 pasos, comprobar response.ok
const res = await fetch('https://jsonplaceholder.typicode.com/users/1');
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const user = await res.json();

// axios: 1 paso, data ya en res.data, 4xx/5xx → catch
const res = await axios.get('https://jsonplaceholder.typicode.com/users/1');
const user = res.data;

GET con axios

// .then()
axios.get('https://jsonplaceholder.typicode.com/users/1')
  .then((res) => console.log(res.data))
  .catch((err) => console.error(err.response?.status, err.message));

// async/await
const res = await axios.get('https://jsonplaceholder.typicode.com/users/1');
console.log(res.data.name, res.data.email);

POST con axios

axios.post('https://jsonplaceholder.typicode.com/posts', {
  title: 'Título',
  body: 'Cuerpo',
  userId: 1
})
  .then((res) => console.log('Creado:', res.data.id))
  .catch((err) => console.error(err));

PUT y DELETE

await axios.put('https://jsonplaceholder.typicode.com/posts/1', { title: 'Nuevo título' });
await axios.delete('https://jsonplaceholder.typicode.com/posts/1');

Errores en axios

En 4xx/5xx, axios lanza y va al catch. El mensaje de la API suele estar en err.response?.data y el status en err.response?.status. 

try {
  const res = await axios.get('https://jsonplaceholder.typicode.com/users/99999');
  console.log(res.data);
} catch (err) {
  console.error('Status:', err.response?.status);
  console.error('Mensaje API:', err.response?.data);
}

En una frase: axios = fetch con JSON automático en res.data y rechazo en 4xx/5xx; el resto (Promesas, async/await, try/catch) es igual.

⚡ 6. async/await — Misma lógica, sintaxis más clara

async/await es “azúcar sintáctica” sobre Promesas: hace lo mismo que .then()/.catch(), pero el código se lee en orden (arriba abajo) como si fuera síncrono.

Dos reglas de oro

  • await = “espera aquí a que la Promesa termine y dame el valor”. Solo dentro de una función async.
  • Una función async siempre devuelve una Promesa (aunque uses return 5, quien la llame recibe una Promesa que se resuelve a 5).

Mismo flujo: .then() vs async/await

// Con .then()
fetch('https://jsonplaceholder.typicode.com/users/1')
  .then((res) => res.json())
  .then((user) => console.log(user.name))
  .catch((err) => console.error(err));

// Con async/await (mismo resultado, más legible)
const fn = async () => {
  try {
    const res = await fetch('https://jsonplaceholder.typicode.com/users/1');
    const user = await res.json();   // res.json() también es Promesa → await
    console.log(user.name);
  } catch (err) {
    console.error(err);
  }
};
fn();

Ejemplo completo: función reutilizable que puedes probar ya

const obtenerUsuario = async (id) => {
  try {
    const res = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const user = await res.json();
    return user;
  } catch (err) {
    console.error('Error:', err);
    return null;
  }
};

// Uso: obtenerUsuario devuelve una Promesa
obtenerUsuario(3).then((u) => console.log(u?.name));

Varias peticiones: en paralelo vs en serie

// En paralelo (más rápido cuando no dependen entre sí)
const [a, b] = await Promise.all([
  fetch('https://jsonplaceholder.typicode.com/users/1').then((r) => r.json()),
  fetch('https://jsonplaceholder.typicode.com/users/2').then((r) => r.json())
]);

// En serie (la 2.ª usa el resultado de la 1.ª)
const u1 = await fetch('.../users/1').then((r) => r.json());
const posts = await fetch(`.../users/${u1.id}/posts`).then((r) => r.json());

En una frase: await pausa la función en esa línea hasta tener el valor; el resto del programa (otros eventos, otras funciones) sigue ejecutándose.

⚠️ 7. Manejo de errores — try/catch y response.ok

Con async/await usas try/catch como en el código normal. Además, como fetch no rechaza en 404/500, conviene comprobar response.ok y lanzar un error con throw para que lo atrape el catch.

Plantilla que puedes copiar

const obtenerDatos = async (url) => {
  try {
    const res = await fetch(url);
    if (!res.ok) throw new Error(`Error ${res.status}`);
    const data = await res.json();
    return data;
  } catch (err) {
    console.error(err);
    return null;  // o throw err si quieres que quien llame maneje el error
  }
};

Para tu API de heladería (localhost:3000) — con fetch

Misma idea, cambiando la URL. Ejemplo: obtener, crear y eliminar sabores.

const obtenerSabores = async () => {
  try {
    const res = await fetch('http://localhost:3000/api/sabores');
    if (!res.ok) throw new Error('Error al cargar sabores');
    return await res.json();
  } catch (err) {
    console.error(err);
    return [];
  }
};

const crearSabor = async (nombre, precio) => {
  const res = await fetch('http://localhost:3000/api/sabores', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ nombre, precio: parseFloat(precio) })
  });
  if (!res.ok) throw new Error('Error al crear');
  return await res.json();
};

const eliminarSabor = async (id) => {
  const res = await fetch(`http://localhost:3000/api/sabores/${id}`, { method: 'DELETE' });
  if (!res.ok) throw new Error('Error al eliminar');
  return true;
};

Lo mismo con axios (más corto: sin response.ok ni .json())

const obtenerSabores = async () => {
  try {
    const { data } = await axios.get('http://localhost:3000/api/sabores');
    return data;
  } catch (err) {
    console.error(err);
    return [];
  }
};

const crearSabor = async (nombre, precio) => {
  const { data } = await axios.post('http://localhost:3000/api/sabores', { nombre, precio: parseFloat(precio) });
  return data;
};

const eliminarSabor = async (id) => {
  await axios.delete(`http://localhost:3000/api/sabores/${id}`);
  return true;
};

⚠️ 8. Errores frecuentes

1. Olvidar await (y que response.json() también es Promesa)

// ❌ response es una Promesa, no el objeto Response
const res = fetch(url);
const data = res.json();  // res.json no existe sobre una Promesa

// ❌ res sí es Response, pero .json() devuelve una Promesa
const res = await fetch(url);
const data = res.json();  // data es una Promesa, no el objeto

// ✅
const res = await fetch(url);
const data = await res.json();

2. No verificar response.ok

// ❌ Con 404, fetch no rechaza; res.json() puede fallar o devolver mensaje de error
const res = await fetch('/api/no-existe');
const data = await res.json();

// ✅
const res = await fetch('/api/sabores');
if (!res.ok) throw new Error(`Error ${res.status}`);
const data = await res.json();

3. Usar await en el “aire” (fuera de una función async)

// ❌ En un script normal no se puede
const data = await fetch(url);  // SyntaxError en muchos entornos

// ✅ Siempre dentro de una función async
const main = async () => {
  const res = await fetch(url);
  const data = await res.json();
  console.log(data);
};
main();

📋 Resumen en 5 ideas

  1. Asíncrono: la tarea tarda; el programa no se bloquea y “reacciona” cuando termina.
  2. Promesa: representa ese resultado futuro; .then() / .catch() para usarlo.
  3. fetch: devuelve una Promesa con response; response.json() devuelve otra Promesa con el JSON. 4xx/5xx no rechazan → hay que chequear response.ok.
  4. axios: igual que fetch en que usa Promesas, pero el JSON va en res.data y 4xx/5xx sí rechazan (caen en catch).
  5. async/await: misma lógica que .then(), sintaxis en orden: await pausa la función hasta tener el valor; errores con try/catch. Sirve con fetch y con axios.

❓ Preguntas frecuentes

¿.then() y async/await hacen lo mismo?

Sí. async/await es otra forma de escribir lo mismo: más legible cuando hay varios pasos seguidos.

¿Dónde puedo usar await?

Solo dentro de una función declarada con async. Si no, hay SyntaxError.

¿Por qué response.ok?

fetch solo rechaza por fallos de red. Si el servidor responde 404 o 500, la Promesa se cumple; el “error” lo ves en response.ok === false. Con axios no aplica: 4xx/5xx rechazan y caen en catch.

¿fetch o axios?

fetch viene en el navegador y Node; axios es una dependencia. Axios suele ser más cómodo: res.data en vez de res.json(), y 4xx/5xx al catch. En React y Node se usa axios muy a menudo.
