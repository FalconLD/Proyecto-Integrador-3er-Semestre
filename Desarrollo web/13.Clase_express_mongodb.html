Clase: Express.js + MongoDB

Conectar tu API Express con MongoDB usando Mongoose — desarrollo backend.

Objetivo

Configurar una conexión entre una aplicación Express y MongoDB usando Mongoose. Crear esquemas, modelos y usarlos en rutas para hacer operaciones CRUD sobre la base de datos. Al final podrás reemplazar archivos JSON o datos en memoria por MongoDB en tu API.

Ruta de la clase: MongoDB → Instalación de MongoDB (Linux, Windows, Mac) → Mongoose → Proyecto Node → Variables de entorno → Conexión → Esquemas y modelos (Reseña) → Rutas /api/resenas → Errores y buenas prácticas.

🍃 1. MongoDB en una frase

MongoDB es una base de datos NoSQL que guarda datos en formato documentos (JSON-like). No usa tablas y filas como PostgreSQL; usa colecciones y documentos.

Conceptos básicos

SQL (PostgreSQL, MySQL) MongoDB (NoSQL)
Base de datos Base de datos
Tabla Colección
Fila / registro Documento
Columna Campo (clave en el documento)

Dónde correr MongoDB

  • Local: Instalas MongoDB en tu PC y te conectas a mongodb://localhost:27017. Útil para desarrollar.
  • MongoDB Atlas: Servicio en la nube gratuito (tier M0). Te dan un connection string (URI) para conectar desde cualquier sitio. No requiere instalar nada en tu máquina.

💻 2. Instalación de MongoDB (Linux, Windows, Mac)

Usamos MongoDB Community Edition. Si prefieres no instalar, usa MongoDB Atlas y salta esta sección.

Linux (Ubuntu / Debian)

Reemplaza jammy por focal en Ubuntu 20.04 o por noble en 24.04.

# 1. Instalar gnupg y curl si no los tienes
sudo apt-get install -y gnupg curl

# 2. Importar la clave GPG de MongoDB
curl -fsSL https://www.mongodb.org/static/pgp/server-8.0.asc | \
  sudo gpg -o /usr/share/keyrings/mongodb-server-8.0.gpg --dearmor

# 3. Añadir el repositorio (ej. Ubuntu 22.04 = jammy)
echo "deb [ signed-by=/usr/share/keyrings/mongodb-server-8.0.gpg ] https://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/8.0 multiverse" | \
  sudo tee /etc/apt/sources.list.d/mongodb-org-8.0.list

# 4. Actualizar e instalar
sudo apt-get update
sudo apt-get install -y mongodb-org

# 5. Iniciar el servicio
sudo systemctl start mongod
sudo systemctl enable mongod   # que arranque con el sistema

# Verificar que está corriendo
sudo systemctl status mongod

Windows

  1. Descarga el instalador .msi desde MongoDB Community Download (elige Windows x64).
  2. Ejecuta el .msi. En el asistente, deja marcada la opción “Install MongoDB as a Service” para que se inicie con Windows.
  3. Si lo instalas como servicio, MongoDB quedará corriendo en localhost:27017. Si no, puedes iniciarlo desde una terminal en la carpeta de instalación (por defecto C:\Program Files\MongoDB\Server\8.0\bin) con mongod.exe.

Alternativa con winget: winget install MongoDB.Server

Mac (Apple Silicon o Intel)

# 1. Añadir el tap de MongoDB y instalar
brew tap mongodb/brew
brew install mongodb-community

# 2. Iniciar el servicio
brew services start mongodb-community

# Detener:  brew services stop mongodb-community

Si no tienes Homebrew: brew.sh

📦 3. Mongoose — el ODM para Node y Express

Para hablar con MongoDB desde Node.js se usa un driver. Mongoose es una capa encima del driver oficial que añade: esquemas (definir la forma de los documentos), validaciones, middlewares y métodos comodos. Es el estándar con Express.

¿Qué hace Mongoose por ti?

  • Gestiona la conexión a MongoDB (conectar, reconectar, errores).
  • Define Esquemas (tipos, requerido, default) y los convierte en Modelos para crear, leer, actualizar y borrar documentos.
  • Validación antes de guardar (ej. campo obligatorio, tipo Number).

🔐 5. Variables de entorno y connection string

La URI de MongoDB (y el puerto de la app) deben ir en .env. Nunca subas .env a Git.

.env — MongoDB local

PORT=3000
MONGODB_URI=mongodb://localhost:27017/heladeria_db

heladeria_db es el nombre de la base. Si no existe, MongoDB la crea al escribir el primer documento. Asegúrate de que MongoDB esté en ejecución (ver sección 2).

.env — MongoDB Atlas

PORT=3000
MONGODB_URI=mongodb+srv://usuario:password@cluster0.xxxxx.mongodb.net/heladeria_db?retryWrites=true&w=majority

Reemplaza usuario, password y la parte del cluster por los de tu proyecto en Atlas. En Atlas: Database → Connect → “Connect your application” → copiar la URI.

.env.example (plantilla para el repo)

PORT=3000
MONGODB_URI=mongodb://localhost:27017/heladeria_db

🔌 6. Crear la conexión a MongoDB

Conviene tener la lógica de conexión en un archivo aparte (ej. src/db.js) y llamarla al arrancar el servidor. Solo debes conectar una vez; Mongoose reutiliza la conexión.

src/db.js

const mongoose = require('mongoose');

const connectDB = async () => {
  try {
    const conn = await mongoose.connect(process.env.MONGODB_URI);
    console.log(`MongoDB conectado: ${conn.connection.host}`);
  } catch (err) {
    console.error('Error al conectar MongoDB:', err.message);
    process.exit(1);
  }
};

module.exports = connectDB;

Conectar antes de escuchar en Express (src/server.js)

require('dotenv').config();
const express = require('express');
const connectDB = require('./db');

const app = express();
app.use(express.json());

// Rutas (las definimos después)
app.get('/api/health', (req, res) => {
  res.json({ ok: true, message: 'API con MongoDB' });
});

// Arrancar: primero conectar a MongoDB, luego escuchar
const PORT = process.env.PORT || 3000;
const start = async () => {
  await connectDB();
  app.listen(PORT, () => {
    console.log(`Servidor en http://localhost:${PORT}`);
  });
};
start();

Orden importante: Conectamos a MongoDB con await connectDB() antes de app.listen(). Si la conexión falla, connectDB hace process.exit(1) y el servidor no llega a escuchar.

📋 7. Esquemas y modelos — Reseñas de helados

Un Esquema describe la forma del documento (campos, tipos, si son obligatorios). Un Modelo es la clase con la que creas, buscas, actualizas y borras documentos en una colección. Usaremos reseñas de helados: autor, sabor del helado, puntuación y texto.

Modelo Reseña (src/models/Resena.js)

const mongoose = require('mongoose');

const resenaSchema = new mongoose.Schema({
  autor:       { type: String, required: true },
  sabor:       { type: String, required: true },   // ej. "Chocolate", "Vainilla"
  puntuacion:  { type: Number, required: true, min: 1, max: 5 },
  texto:       { type: String, required: true }
}, { timestamps: true });  // añade createdAt, updatedAt

const Resena = mongoose.model('Resena', resenaSchema);
module.exports = Resena;

Tipos habituales en Mongoose

  • String, Number, Boolean, Date
  • Array, ObjectId (referencia a otro documento)
  • Opciones: required: true, default: valor, min / max

timestamps: true agrega createdAt y updatedAt automáticamente.

require('dotenv').config();
const mongoose = require('mongoose');
const Resena = require('./models/Resena');

const resenasEjemplo = [ /* las 10 de arriba */ ];

const seed = async () => {
  await mongoose.connect(process.env.MONGODB_URI);
  await Resena.deleteMany({});
  await Resena.insertMany(resenasEjemplo);
  console.log('10 reseñas insertadas');
  await mongoose.connection.close();

🛣️ 8. Rutas que usan el modelo (reseñas)

En las rutas importas el modelo Resena y usas sus métodos. Todos son asíncronos → usa async/await y try/catch.

Métodos útiles del modelo

  • Model.find() → todos los documentos (devuelve array)
  • Model.findById(id) → uno por _id
  • Model.findOne({ campo: valor }) → el primero que cumpla
  • new Model(datos).save() → crear y guardar
  • Model.findByIdAndUpdate(id, datos, { new: true }) → actualizar y devolver el actualizado
  • Model.findByIdAndDelete(id) → borrar

Rutas de reseñas (src/routes/resenasRoutes.js)

const express = require('express');
const Resena = require('../models/Resena');

const router = express.Router();

// GET /api/resenas
router.get('/', async (req, res) => {
  try {
    const resenas = await Resena.find();
    res.json(resenas);
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
});

// GET /api/resenas/:id
router.get('/:id', async (req, res) => {
  try {
    const resena = await Resena.findById(req.params.id);
    if (!resena) return res.status(404).json({ error: 'Reseña no encontrada' });
    res.json(resena);
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
});

// POST /api/resenas
router.post('/', async (req, res) => {
  try {
    const { autor, sabor, puntuacion, texto } = req.body;
    const resena = new Resena({ autor, sabor, puntuacion, texto });
    await resena.save();
    res.status(201).json(resena);
  } catch (err) {
    res.status(400).json({ error: err.message });
  }
});

// PUT /api/resenas/:id
router.put('/:id', async (req, res) => {
  try {
    const resena = await Resena.findByIdAndUpdate(
      req.params.id,
      req.body,
      { new: true, runValidators: true }
    );
    if (!resena) return res.status(404).json({ error: 'Reseña no encontrada' });
    res.json(resena);
  } catch (err) {
    res.status(400).json({ error: err.message });
  }
});

// DELETE /api/resenas/:id
router.delete('/:id', async (req, res) => {
  try {
    const resena = await Resena.findByIdAndDelete(req.params.id);
    if (!resena) return res.status(404).json({ error: 'Reseña no encontrada' });
    res.json({ message: 'Reseña eliminada' });
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
});

module.exports = router;

Montar las rutas en server.js

const resenasRoutes = require('./routes/resenasRoutes');
app.use('/api/resenas', resenasRoutes);

⚠️ 9. Errores y buenas prácticas

Errores de conexión

Si MongoDB no está levantado o la URI es incorrecta, mongoose.connect() lanza. Por eso en connectDB usamos try/catch y process.exit(1) para no seguir sin DB.

Validación de Mongoose

Si envías en POST/PUT datos que no cumplen el esquema (ej. falta autor o puntuacion fuera de 1–5), Mongoose lanza. Ese error cae en el catch de la ruta; puedes responder con res.status(400).json({ error: err.message }).

IDs: ObjectId inválido

Si pasas un id con formato distinto a ObjectId (24 caracteres hex), findById no lanza pero devuelve null. Lo manejas con if (!resena) return res.status(404)....

├── models/
│   └── Resena.js
├── routes/

📋 Resumen

  1. MongoDB: base NoSQL por documentos. Colecciones y documentos (JSON-like). Instalación: Linux (apt), Windows (.msi), Mac (Homebrew).
  2. Mongoose: ODM para Node: conexión, esquemas, modelos, validación.
  3. Conexión: mongoose.connect(MONGODB_URI) en connectDB(); llamar con await antes de app.listen().
  4. Esquema y modelo: ej. Resena con autor, sabor, puntuacion (1–5), texto. mongoose.model('Resena', schema) para find, save, findByIdAndUpdate, findByIdAndDelete.
  5. Rutas: importar el modelo, async/await, try/catch. Las 10 reseñas de ejemplo se pueden cargar con insertMany o por POST.
