Clase: Mensajes de Commit

Aprende a escribir mensajes de commit claros y consistentes — buenas prácticas de desarrollo.

Objetivo

Aprender a escribir mensajes de commit profesionales y consistentes que faciliten el trabajo en equipo y el seguimiento del historial del proyecto. Los mensajes de commit bien escritos son fundamentales para mantener un código organizado y comprensible.

📝 ¿Por qué son importantes los mensajes de commit?

Los mensajes de commit son como notas que explican qué cambios hiciste y por qué. Son fundamentales para el trabajo en equipo y para entender el historial del proyecto.

Beneficios de buenos mensajes de commit

  • Comunicación: Otros desarrolladores (y tú en el futuro) entienden qué cambió y por qué
  • Historial claro: Puedes ver fácilmente qué se hizo en cada momento del proyecto
  • Debugging: Si algo se rompe, puedes identificar qué commit causó el problema
  • Colaboración: Facilita el trabajo en equipo y las revisiones de código
  • Documentación: Los mensajes de commit sirven como documentación del proyecto
  • Rastreabilidad: Puedes vincular commits con tareas o issues del proyecto

¿Qué pasa con mensajes mal escritos?

Mensaje malo Problema
fix ¿Qué se arregló? ¿Dónde? Imposible de entender
cambios Muy vago, no dice nada útil
asdf Sin sentido, no aporta información
actualizacion final ¿Qué se actualizó? ¿Por qué es "final"?

📋 Formato Estándar de Mensajes de Commit

En esta clase aprenderemos un formato específico y consistente para escribir mensajes de commit que facilite el trabajo en equipo y el seguimiento de tareas.

Estructura del mensaje

El formato que usaremos es:

tipo: [Nombre][Tarea] mensaje descriptivo

Componentes del formato

  1. Tipo: Indica qué tipo de cambio es (feat, fix, chore, refactor)
  2. Dos puntos: Separador entre el tipo y el resto del mensaje
  3. Nombre: Nombre de la persona que hace el commit (entre corchetes)
  4. Tarea: Número o identificador de la tarea (entre corchetes)
  5. Mensaje: Descripción clara y concisa del cambio

Ejemplo completo

feat: [Fabian][ICE-2] agregar nuevo componente sabor

Este mensaje indica:

  • Tipo: feat - Es una nueva funcionalidad
  • Autor: Fabian - Fabian hizo este commit
  • Tarea: ICE-2 - Relacionado con la tarea ICE-2
  • Mensaje: agregar nuevo componente sabor - Describe qué se hizo

🏷️ Tipos de Commit

El tipo de commit indica la naturaleza del cambio. Usa el tipo correcto para que el historial sea más claro.

Tipos disponibles

Tipo Cuándo usarlo Ejemplo
feat Cuando agregas una nueva funcionalidad o característica feat: [Fabian][ICE-2] agregar nuevo componente sabor
fix Cuando corriges un bug o error fix: [Maria][ICE-5] corregir error al calcular precio total
refactor Cuando mejoras el código sin cambiar funcionalidad (reorganizar, optimizar) refactor: [Juan][ICE-3] mejorar estructura de funciones en App.jsx
chore Cuando haces cambios que no afectan el código (configuración, dependencias, documentación) chore: [Fabian][ICE-1] actualizar dependencias en package.json

Guía rápida de decisión

  • ¿Agregaste algo nuevo? → feat
  • ¿Arreglaste un error? → fix
  • ¿Mejoraste código existente sin cambiar qué hace? → refactor
  • ¿Cambiaste configuración, dependencias o documentación? → chore

⚠️ Nota importante: En el ejemplo del usuario se escribió "firx" pero el tipo correcto es fix (con "fix", no "firx"). Asegúrate de escribir correctamente el tipo.

👤 Nombre y Tarea

Incluir tu nombre y el número de tarea ayuda a rastrear quién hizo qué y relacionar commits con tareas del proyecto.

Formato del nombre

Escribe tu nombre (o apodo) entre corchetes, sin espacios:

[Fabian]
[Maria]
[Juan]
[Ana]

Formato de la tarea

Escribe el identificador de la tarea entre corchetes. Puede ser:

  • Número de tarea: [ICE-2], [ICE-5]
  • ID de issue: [#123], [#45]
  • Cualquier identificador que use tu equipo

Ejemplos completos

feat: [Fabian][ICE-2] agregar nuevo componente sabor
fix: [Maria][ICE-5] corregir error al calcular precio
refactor: [Juan][ICE-3] mejorar estructura de funciones
chore: [Ana][ICE-1] actualizar dependencias

¿Qué pasa si no tengo número de tarea?

Si estás trabajando en algo que no tiene un número de tarea asignado, puedes omitirlo temporalmente, pero es mejor crear una tarea o usar un identificador temporal:

feat: [Fabian][SIN-TAREA] agregar componente de prueba
# O mejor aún, crea una tarea primero

✍️ El Mensaje Descriptivo

El mensaje debe ser claro, conciso y descriptivo. Debe explicar QUÉ cambió, no CÓMO (el código ya muestra el cómo).

Buenas prácticas para el mensaje

  • Usa minúsculas: Todo en minúsculas (excepto nombres propios si es necesario)
  • Empieza con verbo: Usa verbos en infinitivo o imperativo (agregar, corregir, mejorar)
  • Sé específico: Di exactamente qué cambió
  • Manténlo corto: Idealmente menos de 50 caracteres, máximo 72
  • No uses punto final: El mensaje no termina en punto

Ejemplos: Bueno vs Malo

❌ Malo ✅ Bueno Razón
feat: [Fabian][ICE-2] cambios feat: [Fabian][ICE-2] agregar componente sabor Específico vs vago
fix: [Maria][ICE-5] arreglado fix: [Maria][ICE-5] corregir calculo de precio Dice qué se arregló
feat: [Juan][ICE-3] Agregar Nuevo Componente feat: [Juan][ICE-3] agregar nuevo componente Minúsculas (más consistente)
refactor: [Ana][ICE-1] mejoras varias. refactor: [Ana][ICE-1] mejorar estructura de codigo Específico y sin punto

Verbos comunes para empezar

  • Agregar: agregar, crear, implementar, añadir
  • Corregir: corregir, arreglar, solucionar, reparar
  • Mejorar: mejorar, optimizar, refactorizar, actualizar
  • Eliminar: eliminar, remover, borrar
  • Cambiar: cambiar, modificar, actualizar

💡 Ejemplos Prácticos

Aquí tienes ejemplos reales de cómo escribir mensajes de commit para diferentes situaciones.

Agregar nueva funcionalidad

# Agregaste un nuevo componente
feat: [Fabian][ICE-2] agregar nuevo componente sabor

# Agregaste una nueva ruta en la API
feat: [Maria][ICE-7] agregar endpoint para obtener pedidos

# Agregaste validación de formulario
feat: [Juan][ICE-4] agregar validacion de email en formulario

Corregir errores

# Arreglaste un bug en el cálculo
fix: [Ana][ICE-5] corregir error al calcular precio total

# Solucionaste un problema de renderizado
fix: [Fabian][ICE-8] corregir error al renderizar lista vacia

# Arreglaste un problema de conexión
fix: [Maria][ICE-3] corregir error de conexion a la API

Refactorizar código

# Mejoraste la estructura del código
refactor: [Juan][ICE-6] mejorar estructura de funciones en App.jsx

# Optimizaste el rendimiento
refactor: [Ana][ICE-9] optimizar consultas a la base de datos

# Reorganizaste archivos
refactor: [Fabian][ICE-1] reorganizar componentes en carpetas

Tareas de mantenimiento

# Actualizaste dependencias
chore: [Maria][ICE-2] actualizar dependencias en package.json

# Agregaste documentación
chore: [Juan][ICE-4] agregar documentacion en README

# Cambiaste configuración
chore: [Ana][ICE-1] actualizar configuracion de eslint

Múltiples cambios relacionados

Si haces varios cambios relacionados, puedes hacer commits separados o uno que los agrupe:

# Varios commits pequeños (recomendado)
feat: [Fabian][ICE-2] agregar componente sabor
feat: [Fabian][ICE-2] agregar estilos al componente sabor
feat: [Fabian][ICE-2] agregar validacion al componente sabor

# O un commit que agrupa (si son muy relacionados)
feat: [Fabian][ICE-2] agregar componente sabor completo con estilos y validacion

🔄 Cómo Hacer Commits con este Formato

Aprende cómo usar este formato al hacer commits en Git.

Commit desde la terminal

Usa el comando git commit con el flag -m para el mensaje:

# Ejemplo básico
git add .
git commit -m "feat: [Fabian][ICE-2] agregar nuevo componente sabor"

# Si necesitas un mensaje más largo (opcional)
git commit -m "feat: [Fabian][ICE-2] agregar nuevo componente sabor" \
           -m "El componente incluye validación de entrada y estilos básicos"

Commit desde VS Code

  1. Haz tus cambios en los archivos
  2. Ve a la pestaña "Source Control" (Ctrl+Shift+G)
  3. Escribe tu mensaje en el formato: feat: [Fabian][ICE-2] agregar nuevo componente sabor
  4. Presiona Ctrl+Enter para hacer commit

Ver el historial de commits

Puedes ver todos tus commits con:

# Ver historial completo
git log

# Ver historial más compacto
git log --oneline

# Ver historial con gráfico
git log --oneline --graph

Ejemplo de historial

Con este formato, tu historial se verá así:

feat: [Fabian][ICE-2] agregar nuevo componente sabor
fix: [Maria][ICE-5] corregir error al calcular precio
refactor: [Juan][ICE-3] mejorar estructura de funciones
chore: [Ana][ICE-1] actualizar dependencias
feat: [Fabian][ICE-4] agregar validacion de formulario

¡Muy claro y fácil de entender!

⚠️ Errores Comunes y Cómo Evitarlos

Aprende de los errores más comunes al escribir mensajes de commit.

Errores frecuentes

❌ Error ✅ Correcto Problema
feat:[Fabian][ICE-2] mensaje feat: [Fabian][ICE-2] mensaje Falta espacio después de los dos puntos
feat: [Fabian] [ICE-2] mensaje feat: [Fabian][ICE-2] mensaje No debe haber espacio entre los corchetes
FEAT: [Fabian][ICE-2] mensaje feat: [Fabian][ICE-2] mensaje El tipo debe estar en minúsculas
firx: [Fabian][ICE-2] mensaje fix: [Fabian][ICE-2] mensaje Error de ortografía en el tipo
feat: [Fabian][ICE-2] Mensaje con mayúsculas. feat: [Fabian][ICE-2] mensaje con minusculas Minúsculas y sin punto final
feat: Fabian ICE-2 mensaje feat: [Fabian][ICE-2] mensaje Faltan los corchetes

Checklist antes de hacer commit

  • ✓ ¿El tipo es correcto? (feat, fix, refactor, chore)
  • ✓ ¿Hay dos puntos después del tipo?
  • ✓ ¿Tu nombre está entre corchetes?
  • ✓ ¿El número de tarea está entre corchetes?
  • ✓ ¿El mensaje está en minúsculas?
  • ✓ ¿El mensaje es claro y descriptivo?
  • ✓ ¿No termina en punto?

✨ Buenas Prácticas Adicionales

Más recomendaciones para mejorar tus mensajes de commit.

1. Haz commits frecuentes

Es mejor hacer muchos commits pequeños que pocos commits grandes:

  • ✅ Bien: Un commit por cada funcionalidad pequeña
  • ❌ Mal: Un commit gigante con 20 cambios diferentes

2. Un commit = un cambio lógico

Cada commit debe representar un cambio lógico completo:

# ✅ Bien: Commits separados
feat: [Fabian][ICE-2] agregar componente sabor
feat: [Fabian][ICE-2] agregar estilos al componente
fix: [Fabian][ICE-5] corregir error de validacion

# ❌ Mal: Todo en un commit
feat: [Fabian][ICE-2] agregar componente, estilos y arreglar validacion

3. Revisa antes de hacer commit

Antes de hacer commit, revisa qué estás incluyendo:

# Ver qué archivos cambiaron
git status

# Ver los cambios exactos
git diff

# Si ya agregaste archivos, ver qué se incluirá
git diff --staged

4. No incluyas archivos que no deberían estar

No hagas commit de:

  • Archivos temporales
  • Archivos de configuración personal (como configuraciones del IDE)
  • Archivos generados automáticamente
  • Contraseñas o información sensible

Usa .gitignore para excluir estos archivos automáticamente.

5. Usa el mismo nombre consistentemente

Usa siempre el mismo nombre en tus commits. Si eres "Fabian", siempre usa "Fabian", no alternes con "Fabián", "fabian", etc.

❓ Preguntas Frecuentes

¿Qué pasa si olvido el formato en un commit?

No es el fin del mundo, pero trata de ser consistente. Si te das cuenta inmediatamente después, puedes cambiar el mensaje del último commit con: git commit --amend -m "nuevo mensaje". Si ya lo subiste, es mejor dejarlo y seguir el formato en los siguientes commits.

¿Puedo usar otros tipos además de feat, fix, refactor, chore?

En este curso usaremos estos 4 tipos principales para mantener consistencia. En proyectos más grandes podrías ver otros como docs (documentación), test (tests), style (formato), pero por ahora nos quedamos con estos 4.

¿Qué hago si el mensaje es muy largo?

Si necesitas más de 72 caracteres, puedes usar un mensaje corto seguido de una descripción más larga: git commit -m "mensaje corto" -m "descripcion mas detallada aqui". Pero trata de mantener el mensaje principal corto y claro.

¿Debo usar mi nombre completo o solo el primero?

Usa el nombre con el que te identifiques en el equipo. Puede ser tu primer nombre, apodo, o nombre completo. Lo importante es ser consistente y que tu equipo sepa quién eres.

¿Qué pasa si trabajo en algo que no tiene número de tarea?

Si no hay un número de tarea asignado, puedes omitirlo temporalmente o usar un identificador temporal como [SIN-TAREA] o [PERSONAL]. Pero es mejor crear una tarea primero para mantener el seguimiento.

¿Puedo hacer commits en español o debo usar inglés?

En este curso usaremos español para los mensajes, ya que es más natural para el equipo. En proyectos internacionales o open source, es común usar inglés, pero para proyectos locales en español, el español está perfecto.

🎯 Ejercicio Práctico

Practica escribiendo mensajes de commit correctos para diferentes situaciones.

Ejercicio 1: Identifica el error

¿Qué está mal en estos mensajes de commit?

  1. feat:[Fabian][ICE-2]Agregar componente
  2. FEAT: [Fabian][ICE-2] agregar componente
  3. feat: Fabian ICE-2 agregar componente
  4. feat: [Fabian][ICE-2] Agregar Componente.
  5. firx: [Maria][ICE-5] arreglado
Ver respuestas
  1. Falta espacio después de los dos puntos y después de los corchetes
  2. El tipo debe estar en minúsculas (feat, no FEAT)
  3. Faltan los corchetes alrededor del nombre y la tarea
  4. El mensaje debe estar en minúsculas y sin punto final
  5. Error de ortografía (firx → fix) y mensaje muy vago (arreglado → debería decir qué se arregló)

Ejercicio 2: Escribe el mensaje correcto

Escribe el mensaje de commit correcto para cada situación:

  1. Agregaste un nuevo botón de "Agregar al carrito" (tarea ICE-3, tu nombre es Juan)
  2. Corregiste un error donde el precio se mostraba incorrectamente (tarea ICE-7, tu nombre es Ana)
  3. Reorganizaste las funciones en el archivo utils.js para que sea más legible (tarea ICE-1, tu nombre es Maria)
  4. Actualizaste la versión de React en package.json (tarea ICE-2, tu nombre es Fabian)
Ver respuestas
  1. feat: [Juan][ICE-3] agregar boton agregar al carrito
  2. fix: [Ana][ICE-7] corregir error en visualizacion de precio
  3. refactor: [Maria][ICE-1] reorganizar funciones en utils.js
  4. chore: [Fabian][ICE-2] actualizar version de React

Ejercicio 3: Practica en tu proyecto

Desafío: En tu proyecto actual (o crea uno nuevo), haz al menos 5 commits usando el formato correcto:

  • 1 commit de tipo feat
  • 1 commit de tipo fix
  • 1 commit de tipo refactor
  • 1 commit de tipo chore
  • 1 commit adicional de cualquier tipo

Luego revisa tu historial con git log --oneline y verifica que todos los mensajes sigan el formato correcto.
