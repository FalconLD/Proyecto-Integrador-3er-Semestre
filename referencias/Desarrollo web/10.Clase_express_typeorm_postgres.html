Clase: Express Avanzado + TypeORM + PostgreSQL

Arquitectura limpia, bases de datos reales y código profesional — desarrollo backend.

Objetivo

Aprender a estructurar aplicaciones Express de forma profesional, integrar TypeORM para trabajar con bases de datos, y conectar con PostgreSQL. Migrar tu API de heladería de archivos JSON a una base de datos real con una arquitectura limpia y escalable.

🏗️ Arquitectura Limpia en Express

Organizar el código de forma profesional hace que la aplicación sea más fácil de mantener, escalar y trabajar en equipo.

Estructura de carpetas recomendada

ice-cream-shop-back/
├── src/
│   ├── config/              # Configuraciones
│   │   └── database.js      # Configuración de base de datos
│   ├── models/              # Modelos de datos (TypeORM)

¿Por qué esta estructura?

  • Separation of Concerns: Cada carpeta tiene una responsabilidad específica
  • Escalabilidad: Fácil agregar nuevas funcionalidades
  • Mantenibilidad: Fácil encontrar y modificar código
  • Testing: Más fácil testear componentes aislados
  • Colaboración: Diferentes desarrolladores pueden trabajar en diferentes partes

🐘 PostgreSQL - Introducción

PostgreSQL es una base de datos relacional robusta y gratuita. Vamos a usarla para almacenar nuestros datos de forma profesional.

¿Qué es PostgreSQL?

  • Base de datos relacional (SQL)
  • Open source y gratuita
  • Muy robusta y confiable
  • Usada por empresas grandes (Instagram, Spotify, etc.)
  • Mejor que SQLite para aplicaciones en producción

Instalación de PostgreSQL

Linux (Ubuntu/Debian):

sudo apt update
sudo apt install postgresql postgresql-contrib
sudo systemctl start postgresql
sudo systemctl enable postgresql

macOS:

brew install postgresql
brew services start postgresql

Windows:

Descarga el instalador desde: https://www.postgresql.org/download/windows/

Crear base de datos

# Acceder a PostgreSQL
sudo -u postgres psql

# Crear base de datos
CREATE DATABASE heladeria_db;

# Crear usuario (opcional, puedes usar postgres)
CREATE USER heladeria_user WITH PASSWORD 'tu_password';
GRANT ALL PRIVILEGES ON DATABASE heladeria_db TO heladeria_user;

# Salir
\q

Verificar conexión

# Conectar a la base de datos
psql -U postgres -d heladeria_db

# O si creaste un usuario
psql -U heladeria_user -d heladeria_db

🗄️ TypeORM - Introducción

TypeORM es un ORM (Object-Relational Mapping) que permite trabajar con bases de datos usando objetos JavaScript en lugar de escribir SQL directamente.

¿Qué es un ORM?

  • ORM: Object-Relational Mapping (Mapeo Objeto-Relacional)
  • Traduce entre objetos JavaScript y tablas de base de datos
  • Escribe menos código SQL manual
  • Más seguro (previene SQL injection)
  • Más fácil de mantener

Instalación

Ya instalamos TypeORM, pg y reflect-metadata en la sección de instalación anterior.

  • typeorm: El ORM principal
  • pg: Driver de PostgreSQL para Node.js
  • reflect-metadata: Necesario para que TypeORM funcione con decoradores

Configuración básica

// src/config/database.js
const { DataSource } = require('typeorm');
require('dotenv').config();

// Importar entidades
const SaborSchema = require('../models/Sabor');

const AppDataSource = new DataSource({
  type: 'postgres',
  host: process.env.DB_HOST || 'localhost',
  port: parseInt(process.env.DB_PORT) || 5432,
  username: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  synchronize: false, // No sincronizar automáticamente (creamos tablas manualmente)
  logging: process.env.NODE_ENV === 'development',
  entities: [SaborSchema], // Pasar las entidades directamente
});

module.exports = AppDataSource;

📊 Crear Modelos con TypeORM

Los modelos definen la estructura de tus tablas en la base de datos usando clases JavaScript.

Modelo de Sabor

// src/models/Sabor.js
const { EntitySchema } = require('typeorm');

const SaborSchema = new EntitySchema({
  name: 'Sabor',
  tableName: 'sabores',
  columns: {
    id: {
      type: 'int',
      primary: true,
      generated: true,
    },
    nombre: {
      type: 'varchar',
      length: 100,
    },
    precio: {
      type: 'decimal',
      precision: 10,
      scale: 2,
    },
    disponible: {
      type: 'boolean',
      default: true,
    },
    createdAt: {
      type: 'timestamp',
      default: () => 'CURRENT_TIMESTAMP',
    },
    updatedAt: {
      type: 'timestamp',
      default: () => 'CURRENT_TIMESTAMP',
      onUpdate: 'CURRENT_TIMESTAMP',
    },
  },
});

module.exports = SaborSchema;

Decoradores de TypeORM

Los decoradores más comunes:

  • @Entity('nombre_tabla') - Define una entidad (tabla)
  • @PrimaryGeneratedColumn() - ID auto-incremental
  • @Column({ type: 'tipo' }) - Define una columna
  • @CreateDateColumn() - Fecha de creación automática
  • @UpdateDateColumn() - Fecha de actualización automática

🎮 Controllers (Controladores)

Los controladores contienen la lógica de negocio y manejan las peticiones HTTP.

Controller de Sabores

// src/controllers/saboresController.js
const AppDataSource = require('../config/database');
const Sabor = require('../models/Sabor');

// Obtener todos los sabores
async function obtenerTodos(req, res) {
  try {
    const saborRepository = AppDataSource.getRepository(Sabor);
    const sabores = await saborRepository.find({
      order: { id: 'ASC' }
    });
    res.json(sabores);
  } catch (error) {
    console.error('Error al obtener sabores:', error);
    res.status(500).json({ error: 'Error al obtener sabores' });
  }
}

// Obtener un sabor por ID
async function obtenerPorId(req, res) {
  try {
    const { id } = req.params;
    const saborRepository = AppDataSource.getRepository(Sabor);
    const sabor = await saborRepository.findOne({ where: { id: parseInt(id) } });
    
    if (!sabor) {
      return res.status(404).json({ error: 'Sabor no encontrado' });
    }
    
    res.json(sabor);
  } catch (error) {
    console.error('Error al obtener sabor:', error);
    res.status(500).json({ error: 'Error al obtener sabor' });
  }
}

// Crear un nuevo sabor
async function crear(req, res) {
  try {
    const { nombre, precio } = req.body;
    
    // Validación básica
    if (!nombre || !precio) {
      return res.status(400).json({ 
        error: 'Nombre y precio son requeridos' 
      });
    }
    
    const saborRepository = AppDataSource.getRepository(Sabor);
    const nuevoSabor = saborRepository.create({
      nombre: nombre.trim(),
      precio: parseFloat(precio),
      disponible: true
    });
    
    const saborGuardado = await saborRepository.save(nuevoSabor);
    res.status(201).json(saborGuardado);
  } catch (error) {
    console.error('Error al crear sabor:', error);
    res.status(500).json({ error: 'Error al crear sabor' });
  }
}

// Actualizar un sabor
async function actualizar(req, res) {
  try {
    const { id } = req.params;
    const { nombre, precio, disponible } = req.body;
    
    const saborRepository = AppDataSource.getRepository(Sabor);
    const sabor = await saborRepository.findOne({ where: { id: parseInt(id) } });
    
    if (!sabor) {
      return res.status(404).json({ error: 'Sabor no encontrado' });
    }
    
    // Actualizar solo los campos proporcionados
    if (nombre !== undefined) sabor.nombre = nombre.trim();
    if (precio !== undefined) sabor.precio = parseFloat(precio);
    if (disponible !== undefined) sabor.disponible = disponible;
    
    const saborActualizado = await saborRepository.save(sabor);
    res.json(saborActualizado);
  } catch (error) {
    console.error('Error al actualizar sabor:', error);
    res.status(500).json({ error: 'Error al actualizar sabor' });
  }
}

// Eliminar un sabor
async function eliminar(req, res) {
  try {
    const { id } = req.params;
    const saborRepository = AppDataSource.getRepository(Sabor);
    const resultado = await saborRepository.delete(parseInt(id));
    
    if (resultado.affected === 0) {
      return res.status(404).json({ error: 'Sabor no encontrado' });
    }
    
    res.json({ mensaje: 'Sabor eliminado exitosamente' });
  } catch (error) {
    console.error('Error al eliminar sabor:', error);
    res.status(500).json({ error: 'Error al eliminar sabor' });
  }
}

module.exports = {
  obtenerTodos,
  obtenerPorId,
  crear,
  actualizar,
  eliminar
};

🛣️ Routes (Rutas)

Las rutas definen los endpoints de tu API y conectan las peticiones HTTP con los controladores.

Rutas de Sabores

// src/routes/saboresRoutes.js
const express = require('express');
const router = express.Router();
const saboresController = require('../controllers/saboresController');

// GET /api/sabores - Obtener todos los sabores
router.get('/', saboresController.obtenerTodos);

// GET /api/sabores/:id - Obtener un sabor por ID
router.get('/:id', saboresController.obtenerPorId);

// POST /api/sabores - Crear un nuevo sabor
router.post('/', saboresController.crear);

// PUT /api/sabores/:id - Actualizar un sabor
router.put('/:id', saboresController.actualizar);

// DELETE /api/sabores/:id - Eliminar un sabor
router.delete('/:id', saboresController.eliminar);

module.exports = router;

Registrar rutas en el servidor

// src/server.js
require('reflect-metadata');
const express = require('express');
const AppDataSource = require('./config/database');
const saboresRoutes = require('./routes/saboresRoutes');

const app = express();
app.use(express.json());

// Middleware de CORS (si tu frontend está en otro puerto)
app.use((req, res, next) => {
  res.header('Access-Control-Allow-Origin', '*');
  res.header('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE');
  res.header('Access-Control-Allow-Headers', 'Content-Type');
  next();
});

// Rutas
app.use('/api/sabores', saboresRoutes);

// Ruta de prueba
app.get('/', (req, res) => {
  res.json({ mensaje: 'API de Heladería funcionando' });
});

// Inicializar base de datos y servidor
AppDataSource.initialize()
  .then(() => {
    console.log('✅ Base de datos conectada');
    
    const PORT = process.env.PORT || 3000;
    app.listen(PORT, () => {
      console.log(`🚀 Servidor corriendo en puerto ${PORT}`);
      console.log(`📡 API disponible en http://localhost:${PORT}/api`);
    });
  })
  .catch((error) => {
    console.error('❌ Error al conectar con la base de datos:', error);
    process.exit(1);
  });

⚠️ Manejo de Errores

Un middleware centralizado para manejar errores hace el código más limpio y consistente.

Middleware de manejo de errores

// src/middleware/errorHandler.js
function errorHandler(err, req, res, next) {
  console.error('Error:', err);
  
  // Errores de validación de TypeORM
  if (err.name === 'QueryFailedError') {
    return res.status(400).json({ 
      error: 'Error en la consulta a la base de datos',
      detalles: err.message 
    });
  }
  
  // Error 404
  if (err.status === 404) {
    return res.status(404).json({ error: err.message || 'Recurso no encontrado' });
  }
  
  // Error 500 (genérico)
  res.status(err.status || 500).json({ 
    error: err.message || 'Error interno del servidor' 
  });
}

module.exports = errorHandler;

Usar el middleware de errores

// src/server.js
const errorHandler = require('./middleware/errorHandler');

// ... resto del código ...

// Middleware de errores (debe ir al final, después de todas las rutas)
app.use(errorHandler);

🔧 Operaciones Comunes con TypeORM

Referencia rápida de las operaciones más comunes que harás con TypeORM.

Obtener repositorio

const saborRepository = AppDataSource.getRepository(Sabor);

Operaciones CRUD

// CREATE - Crear
const nuevoSabor = saborRepository.create({ nombre: 'Vainilla', precio: 2.50 });
const saborGuardado = await saborRepository.save(nuevoSabor);

// READ - Leer todos
const sabores = await saborRepository.find();

// READ - Leer uno
const sabor = await saborRepository.findOne({ where: { id: 1 } });

// READ - Con condiciones
const saboresDisponibles = await saborRepository.find({ 
  where: { disponible: true },
  order: { precio: 'ASC' }
});

// UPDATE - Actualizar
sabor.precio = 3.00;
await saborRepository.save(sabor);

// DELETE - Eliminar
await saborRepository.delete(1);

// DELETE - Eliminar con condición
await saborRepository.delete({ disponible: false });

Consultas más avanzadas

// Buscar con múltiples condiciones
const sabores = await saborRepository.find({
  where: [
    { disponible: true },
    { precio: { $lt: 3.00 } } // Menor que 3.00
  ],
  order: { nombre: 'ASC' },
  take: 10, // Limitar a 10 resultados
  skip: 0   // Saltar los primeros 0
});

// Contar registros
const total = await saborRepository.count({ where: { disponible: true } });

// Buscar uno o lanzar error
const sabor = await saborRepository.findOneOrFail({ where: { id: 1 } });

✅ Buenas Prácticas

Sigue estas recomendaciones para mantener tu código limpio y profesional.

1. Separación de responsabilidades

  • Models: Solo definen la estructura de datos
  • Controllers: Manejan la lógica de negocio y HTTP
  • Routes: Solo definen las rutas
  • Middleware: Funciones reutilizables (validación, autenticación, etc.)

2. Validación de datos

// src/utils/validaciones.js
function validarSabor(data) {
  const errores = [];
  
  if (!data.nombre || data.nombre.trim() === '') {
    errores.push('El nombre es requerido');
  }
  
  if (!data.precio || isNaN(data.precio) || data.precio <= 0) {
    errores.push('El precio debe ser un número mayor a 0');
  }
  
  return {
    valido: errores.length === 0,
    errores
  };
}

module.exports = { validarSabor };

3. Manejo de errores consistente

  • Siempre usa try/catch en funciones async
  • Retorna códigos de estado HTTP apropiados
  • Proporciona mensajes de error claros
  • Usa un middleware centralizado para errores

4. Variables de entorno

  • Nunca hardcodees credenciales en el código
  • Usa .env para configuración
  • Agrega .env a .gitignore
  • Proporciona .env.example como plantilla

5. Código limpio

  • Nombres descriptivos para variables y funciones
  • Funciones pequeñas y con una sola responsabilidad
  • Comenta código complejo, no lo obvio
  • Mantén la consistencia en el estilo de código

❓ Preguntas / Mini desafío

¿Cuál es la diferencia entre un modelo y un controlador?

Un modelo define la estructura de datos (la tabla en la base de datos). Un controlador contiene la lógica de negocio y maneja las peticiones HTTP (qué hacer cuando alguien hace GET, POST, etc.).

¿Por qué usar TypeORM en lugar de escribir SQL directamente?

TypeORM te permite trabajar con objetos JavaScript en lugar de escribir SQL manual. Es más seguro (previene SQL injection), más fácil de mantener, y el código es más legible. Además, TypeORM maneja automáticamente muchas cosas como conexiones, transacciones, etc.

¿Qué hace synchronize: true en TypeORM?

synchronize: true hace que TypeORM sincronice automáticamente tus modelos con la base de datos. Si cambias un modelo, TypeORM actualiza la tabla automáticamente. Es útil en desarrollo, pero nunca debe usarse en producción porque puede perder datos. En producción, usa migraciones.

¿Por qué separar código en controllers, routes, y models?

La separación hace el código más organizado, fácil de mantener, y escalable. Si necesitas cambiar cómo se obtienen los datos (modelo), no afecta cómo se manejan las peticiones HTTP (routes). Si necesitas cambiar la lógica de negocio (controller), no afecta la estructura de datos (modelo). Esto se llama "Separation of Concerns".

¿Qué es un repositorio en TypeORM?

Un repositorio es un objeto que proporciona métodos para trabajar con una entidad específica (como Sabor). Te permite hacer operaciones CRUD (Create, Read, Update, Delete) sin escribir SQL. Obtienes un repositorio con AppDataSource.getRepository(Entity).

🎯 Mini desafío final

Desafío - Migrar tu API a Express + TypeORM + PostgreSQL:

  1. Instala PostgreSQL y crea una base de datos llamada heladeria_db
  2. Instala las dependencias: typeorm, pg, reflect-metadata, dotenv
  3. Crea la estructura de carpetas siguiendo el ejemplo de esta clase
  4. Crea el modelo Sabor con TypeORM (id, nombre, precio, disponible, createdAt, updatedAt)
  5. Configura la conexión a PostgreSQL en src/config/database.js
  6. Crea el controller con todas las operaciones CRUD usando TypeORM
  7. Crea las rutas y conéctalas con el controller
  8. Migra tu API de archivos JSON a PostgreSQL
  9. Prueba todos los endpoints: GET, POST, PUT, DELETE
  10. Conecta tu frontend React (debe funcionar igual, solo cambia la URL si es necesario)

💡 Tip: Empieza con la conexión a la base de datos y el modelo. Luego crea un endpoint simple (GET) para verificar que todo funciona. Después agrega los demás endpoints uno por uno.
